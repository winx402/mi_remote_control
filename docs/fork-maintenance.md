# Fork 维护与 Codex 预设

本 fork 保留上游的应用名称、Bundle ID 和设备协议。新增统一构建安装入口、可重复应用的 Codex 场景，以及 SIGINT/SIGTERM 的正常清理路径。

## 本机构建与安装

首次按上游 `scripts/setup-signing.sh` 建立本机 `MiRemote Dev` 签名身份，然后运行：

```sh
./script/build_and_run.sh --verify
```

入口复用 `scripts/package.sh`，构建并验签成功后再停止旧进程，安装到 `/Applications/MiRemote.app` 并启动。已有安装会保存在同目录的 `.miremote-backup.*` 临时备份中。也支持 `--logs` 和 `--debug`；调试时使用已安装 bundle 内的二进制。Codex 的 Run action 已连接到该入口。

证书、私钥、钥匙串授权、macOS 隐私权限和设备记录只保留本机，不提交仓库。重建时保持同一签名身份与安装路径；权限状态仍应以系统设置和应用体检为准。

## 应用 Codex 场景

先从菜单退出 MiRemote，再执行：

```sh
python3 scripts/apply-codex-profile.py --dry-run
python3 scripts/apply-codex-profile.py
open /Applications/MiRemote.app
```

源预设是 `Resources/codex-profile.patch.json`。脚本保留其他应用和设备设置，完整替换已确认的全局快捷键与 Codex 场景，避免遗留旧手势。已有配置会在本机配置目录的 `backups/` 中备份；新配置从当前二进制导出的完整默认配置生成，再合并预设。过旧的配置会要求先启动新版应用完成迁移，不会直接抬高版本号。

`--binary` 可指定其他构建产物，`--config` 可指定独立测试配置；两个纯 CLI 命令 `--print-default-config` / `--validate-config <path>` 不启动蓝牙或按键引擎。

### 使用方式

新版将 `globalShortcuts` 与 App 的 `profiles` 分开。全局保留手势先于应用配置解析；应用配置不能覆盖它们，系统菜单和 Dock 的方向捕获优先。主页、菜单、TV 配置双击，单击等待 250ms 判定；方向键、OK、返回不加双击等待。普通长按 600ms，左右切桌面长按 650ms，返回退出应用长按 1200ms。

| 全局操作 | 按键 |
| --- | --- |
| 打开或聚焦 Codex | TV 单击 |
| 回上一个应用 | TV 双击 |
| 发送 Control＋左／右（⌃← / ⌃→） | 左／右长按 650 ms |
| 显示 macOS 桌面 | 主页双击 |
| 全局操作面板 | 菜单双击 |
| 唤起／退出 Dock 应用选择 | 菜单长按 |
| 正常退出当前应用 | 返回长按 1.2 秒 |
| 音量（按住连续调节） | 音量＋／－ |
| 电视、Mac 与应用操作面板 | 电源单击 |

电源面板按“小米电视／这台 Mac／应用”分组，同类按钮横排，上下切分类、左右在类内选按钮，保留各类上次列并跳过不可用项。提供电视唤醒、待机、音量、Mac 休眠／关机、退出当前 App、退出抖音及取消。选项采用数据目录，后续可追加能力；默认选中取消。OK 或鼠标点击明确选项才执行，电视操作不会回落到 Mac 电源动作。面板方向优先于全局左右长按，避免选项时切桌面。Mac 仍走正常 System Events 电源流程，不使用强制关机；首次实际执行可能要求自动化授权。应用退出使用打开面板前捕获的目标并保留保存／取消流程，不强杀进程。音量成功后保留面板，其余成功后关闭；错误回到取消并保留反馈。

### 小米电视联动

“通用 → 小米电视”保存本机专属的 `television` 配置（enabled、局域网 IPv4 host、port，默认 6091），未配置时不连接电视。可选择遥控器音量键控制小米电视或 Mac；电视未连接时不把电视指令误发为 Mac 音量或关机。本机地址不进入源预设与仓库。连接检查仅验证服务 TCP 可达，不代表电视屏幕正在开启。

采用 MiLink 本地协议，音量使用 Android KeyCode 24／25；明确命名的“待机”使用 `KEYCODE_SLEEP` 223，唤醒使用 `KEYCODE_WAKEUP` 224（已醒时无作用），不使用开关切换键 26。遥控器电源键尝试一次224，已开机时不关机；面板已打开时再次电源仍尝试唤醒并收起面板，覆盖电视在面板打开期间被其他遥控器待机的情况。菜单栏打开面板不会主动唤醒电视。每次命令成对发送 DOWN／UP，等待两条匹配确认后才报告送达；入队起 4 秒限时、最多 8 个请求、配置变化会取消旧目标，模糊失败不自动重发。不能以 TCP 可达或 ACK 判断屏幕是否亮着。

真正关机与待机已经分开：本轮用户选择先验证待机唤醒，真关机入口暂不可用，`tv_off`/`--tv off`明确失败，不再发送待机。后续可验证电视原生电源菜单；真关机后如果网络服务停止，224无法送达，能否网络开机要单独实测 WOL/CEC/IR 等恢复通路，不能以记录的上次操作假装当前电源状态。

脚本入口不启动 GUI、蓝牙或按键映射，可以和 GUI 并行。示例中的配置来自本机，不在命令行重复暴露地址：

```sh
/Applications/MiRemote.app/Contents/MacOS/miremote --tv status
/Applications/MiRemote.app/Contents/MacOS/miremote --tv volume-up
/Applications/MiRemote.app/Contents/MacOS/miremote --tv volume-down
/Applications/MiRemote.app/Contents/MacOS/miremote --tv standby
/Applications/MiRemote.app/Contents/MacOS/miremote --tv wake
python3 scripts/test-television-client.py --binary /Applications/MiRemote.app/Contents/MacOS/miremote
```

`--tv` 可另带 `--config 路径`；`standby`与`wake`只作用于电视，绝不关闭 Mac。loopback 测试验证真实 CLI 的成对报文、分片／乱序确认、少确认不重发、待机/唤醒键码、拒绝把off混作待机，以及通用 `--run-action` 的异步等待，所有测试只连接本机假电视。协议事实参考 [Mi TV Remote](https://github.com/EndLess728/MiTV-Remote) 和 [Android KeyEvent](https://developer.android.com/reference/android/view/KeyEvent#KEYCODE_SLEEP)，本项目未复制第三方客户端代码。

### 其他按键

返回长按使用独立全局 `quit_app` 动作，请求当前前台应用正常退出，保留应用自己的保存／取消流程。一次按住只请求一次，松手不补发返回；单击仍执行当前应用原有返回操作。退出前会释放鼠标拖拽并收起临时面板。鼠标模式仍可用返回单击或闲置 20 秒退出。

长按菜单进入真实 macOS Dock 的应用选择模式；四个方向都沿 App 图标顺序选择，OK 打开／激活，返回取消，闲置后自动退出。适配 Dock 的左侧、底部、右侧位置与自动隐藏。Dock 模式中左右按键只选 App；退出模式后恢复全局左右长按。选择只通过系统键盘和公开 Accessibility 接口，不改 Dock 的固定项与布局。

系统菜单顶部的常用 App 默认跟随 Dock 固定项，最多 6 个；可在“通用 → 系统功能菜单 · 常用应用”自定义、排序或隐藏。可选 `menuFavoriteApps` 保存 bundle ID 列表，具体个人选择只保留在本机配置中。菜单打开时四方向按下即移动，关闭菜单后恢复全局左右长按。菜单同时支持遥控器和鼠标；退出、锁屏等项目仍要求长按确认。

| Codex 专用操作 | 按键 |
| --- | --- |
| 会话列表 | 主页单击 |
| 新建会话 | 主页长按 |
| 原生上下方向键（按住由系统连续响应） | 上／下 |
| 上一个／下一个实际会话 | 左／右 |
| 确认或发送 | OK 单击，取决于当前焦点 |
| 取消／关闭命令框 | 返回单击 |
| 命令菜单 | 菜单单击 |
| 模型选择器 | TV 长按 |
| 聚焦输入框 | 语音键单击 |
| 听写（仍需额外配置语音工具） | 语音键长按，松开只结束听写 |

上表的方向／OK 行为适用于“保留原有按键”模式；开启下文“应用内遥控”后，方向／OK 由所选按钮或分区模式接管。保留原有按键时，Codex 上下键直接发送原生方向键，不识别滚动区域，也不弹滚动失败提示；左右键通过 Accessibility 识别明确的会话菜单，菜单不兼容时回落到可选会话列表。会话列表使用本机官方 App Server 元数据，不创建会话、不启动模型任务，需要已安装的 Codex CLI，最多显示最近 500 条。

左右长按通过专用 `space_left`／`space_right` 动作发送 Control＋左／右（⌃← / ⌃→），完整发送 Control 按下、箭头按下／抬起、Control 抬起。一次按住只切一次，松手不补发单击。应用按钮预选可在按下时立即显示；输入框、原生菜单等有副作用的方向操作仅在短按松手后提交，长按不会先编辑文字或切视频。其他应用短按在松手时提交，没有 250ms 双击等待。发送全局组合键时退出鼠标模式并释放拖拽。

| 鼠标模式操作 | 按键 |
| --- | --- |
| 移动指针／滚动 | 方向键 |
| 慢速／快速 | 主页单击 |
| 指针／滚轮模式 | TV 长按 |
| 左击／右击 | OK 单击／菜单单击 |
| 锁定拖拽，再按 OK 释放 | OK 长按 |
| 退出 | 返回单击或闲置 20 秒 |

鼠标状态和速度档持续显示；退出、断开、切全局面板或闲置退出均释放拖拽鼠标键。慢速 1→3、快速 3→12 坐标单位／tick，0.8 秒加速，对角线归一化。语音短按不启动音频或听写；长按门控保留有界预录音，语音模式关闭时不输出音频。

应用名称可能显示 ChatGPT，Codex 场景仍绑定 `com.openai.codex`；同一进程的 ChatGPT/Work 模式也共用该标识。全局快捷键摘要在 MiRemote“通用”页显示。旧配置缺少 `globalShortcuts` 时保留上游路由；应用本套装会完整替换已确认的全局保留手势和 Codex 场景，保留其他应用配置与设备设置，并在本机备份旧配置。

### 验证与边界

```sh
.build/miremote --self-test
.build/miremote --render-system-menu .build/system-menu-preview.png
git diff --check
bash -n script/build_and_run.sh
```

自检只验证逻辑。真实按键应先在独立空白文档中测试 Return、删除、鼠标模式，再在 Codex 测试命令菜单和模型选择；不要在含有待发送文字的聊天输入框测试 Return。“识别按键”页仍会执行映射，不是隔离测试环境。

工作区组合键发送时保留 Quartz 为箭头／功能键生成的 Fn、数字键盘标记，并完整维护修饰键的通用位和设备位。覆盖这些标记可能导致应用内按键有效、系统切换空间无响应。自检检查实际构造但不发送的 Ctrl＋左右事件，验证事件类型、键码、必要标记及最终修饰状态归零；实际切换仍需实机验收。

上游仍有设备来源过滤限制：全局事件 tap 会把真实键盘的 F13–F20、小键盘 Clear、除号和乘号当成中转输入。使用这些键时应完全退出 MiRemote；暂停只卸载设备映射，不能完全避开该限制。安全输入期间遥控器方向键也可能不能正常工作。语音是独立的可选配置，按键控制不依赖 BlackHole 或输入法。

### 应用内遥控

“通用 → 应用内遥控”按 App 保存三种行为：保留原有按键、按钮导航、分区导航。未配置的 App 不接管。ChatGPT 与抖音默认采用四向按钮导航；分区导航保留为可选项。

按钮导航使用当前窗口实际可见、可操作的辅助功能控件：四个方向只移动蓝色选中框，OK 才激活。每次根据当前控件位置计算，优先同排同列，无对齐候选时按距离软评分选择斜向控件，不用固定坐标或把所有面板作为必经层级。未发现按钮时提示，不盲发原生箭头。分区导航左右移动区域，上下按区域执行控件选择、辅助功能滚动或应用原生视频方向操作。输入框经 OK 聚焦后进入输入模式，方向键编辑光标，OK 回车，返回退出输入并恢复导航。语音键的既有聚焦输入操作也会进入输入模式。

独立全局手势仍优先。应用内左右快速单击分别移动虚拟选择，不再识别全局左右双击。左右长按触发前不发原生方向事件或开始连发；触发后取消在途预选并切桌面，直到松手不会继续导航。菜单和 Dock 打开时暂时暂停应用导航。返回长按仍退出当前 App。窗口、控件位置或应用改变会清掉旧选择，避免操作与旧蓝框不一致的目标。

通用部分沉淀在 `AppNavigationAccessibility`（后台控件发现、缓存、动作验证）、`AppNavigationGeometry`（四向选择与区域划分）、`ApplicationNavigationController`（会话、输入与取消）和 `NavigationFocusOverlay`。分区使用当前 AX 容器父子关系、列表、分栏和滚动区，父容器直接控件与内层列表分别归属；匿名同集合包装链会压缩。缺少容器信息时只用实际控件或滚动区降级，不按窗口比例虚构侧栏。`appNavigationProfiles` 的 `mode` 可为 `native`／`buttons`／`regions`，`layout` 的 `automatic`／`chat`／`video` 只补充纵向操作语义。自绘界面没有提供可操作控件时，无法承诺通用导航；OK 不会无选择地发送回车。当前版本不使用截图识别、聊天正文或输入框内容，也不保存界面数据。

采集最多遍历 64 层，仍受节点数量与后台总耗时限制；不以父容器能否点击决定是否遍历子控件。身份去重使用 hash 分桶后比较实际元素；子节点分批读取不兼容时采用有界兼容读取，超时或截断标记为未完成，不当作正常空树。常规消息允许 120ms，超时可在剩余总预算内有限重试；查询与点击前校验共用同样的读取兼容策略。

排查抖音时可从 MiRemote 应用菜单选择“检查抖音导航…”，它会切到已运行的抖音，只运行生产采集路径，不移动选择、发送按键或点击。结果在“通用 → 应用内遥控 → 导航诊断结果”折叠区中，仅含数量、角色、错误码和耗时，不含控件标签、聊天内容、URL 或坐标，不写入文件。扫描完整仅说明采集完成，实际方向选择与 OK 激活仍需遥控器验收。

开源方案调研参考：[Scoot](https://github.com/mjrusso/scoot) 提供 AX 控件标记与网格定位；[Vimac](https://github.com/nchudleigh/vimac) 提供控件标记和滚动模式，其 README 已指向后继产品 Homerow；[Spray Can](https://github.com/Kymer0615/spray_can) 结合 AX、本机 Apple Vision OCR 和网格，官方文档明确 OCR 只识别文字而不保证可点击，第三方应用覆盖仍需实测；[OmniParser](https://github.com/microsoft/OmniParser) 通过截图和模型解析交互元素，需要额外运行时与权重。当前实现只采用动态位置导航的设计思路，未引入这些项目的代码、安装程序、截图识别或模型依赖。后续若需要补充抖音自绘控件，可评估可选本机 OCR／网格后备；识别来源应与四向选择和点击验证分开，不能把识别到文字直接当作可点击按钮。

### 微信输入法与连续收音诊断

新默认语音工具为微信输入法，触发键为 Fn，现有按住触发方式保持到遥控器连续收音实测通过。微信输入法接收遥控器 PCM 仍需要 BlackHole 2ch 等音频桥接；BlackHole 可免费安装。更换工具默认值不代表已完成端到端出字验证，也不会自动开启关闭的语音模式。

MiRemote 应用菜单的“验证遥控器连续收音…”打开独立诊断面板。点击“开始测试”后，15 秒内按住遥控器语音键说话约 2 秒，再松开；松手 1 秒后继续说话并等待结果。A 阶段暂缓发送 MIC_CLOSE，观察 6 秒；若没有持续有效 PCM，关闭旧流后仅发送一次已知的 MIC_OPEN，B 阶段再观察 5 秒。两阶段均排除最初 1 秒，不能将蓝牙包、写入成功或 STREAM_START 当作实际声音证据。

报告同时列出按住阶段的基线；基线没有有效 PCM 时直接报告证据不足，不执行 B 阶段。同一已识别会话重复发送 START 只计数，不重置解码器或延长时限；会话 ID 改变或无法确认的重复事件仍终止诊断。

诊断仅在内存统计包数、有效 PCM 和电平，不保存、播放或送往识别服务；结束、取消、超时和断连均清理会话，并在链路允许时请求关闭麦克风。结果只证明本次短窗口，不能推导长期收音或按一下开始／再按一下停止已经可用。关闭面板可取消测试；长按返回会请求退出当前前台应用。

## 同步上游

`origin` 指向个人 fork，`upstream` 指向原项目。在干净工作区中拉取上游并审查差异，再选择合并或变基；存在本地改动时先保留，不覆盖配置。

```sh
git fetch upstream
git log --oneline --left-right HEAD...upstream/main
git diff HEAD...upstream/main
```

合并后重新构建、自检并检查真实按键。只推送源码、预设和通用开发入口；本机配置、日志、证书与设备数据保持在仓库外或忽略目录内。
